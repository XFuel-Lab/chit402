## What This Contract Does

### Core Capabilities

1. **AI Task Routing** — Accepts ibcTFUEL-denominated AI task intents from any agent on Osmosis.
   Routes to Theta EdgeCloud (primary), Akash, Bittensor, or other DePIN providers.

2. **ZK Proof Settlement** — Settles tasks with SP1 ZK proofs (Groth16/PLONK) generated by the
   XFuel SP1 prover on Theta EdgeCloud. Uses nullifier-based replay protection.

3. **A2A Messaging** — Enables ZK-verified agent-to-agent communication with escrow-backed bids
   and Poseidon identity commitments for privacy-preserving agent registration.

4. **Fee Collection** — Routes 0.5–1% task fees to `FeeCollector.wasm` for forwarding back to
   Theta via IBC → CoreRevenueSplitter (30% BBB / 30% GET / 25% Stakers / 15% Treasury).

5. **Batch Settlement** — Processes up to 20 tasks in a single transaction for gas efficiency.

### Message Types Supported

```
ComputeBid        — Agent bids for GPU resources with ZK-verified escrow
ComputeResult     — Provider attests job completion with output hash
InferenceRequest  — Route ML inference to optimal provider
CapabilityQuery   — Discover agent capabilities across chains
DataAttestation   — Certify dataset provenance on-chain
```

### Chain Routing

```
ChainId::Theta       → Theta EVM (origin chain, EdgeCloud compute)
ChainId::Osmosis     → Osmosis (settlement, BTC/AI pools)
ChainId::Akash       → GPU compute marketplace (IBC-native)
ChainId::Bittensor   → TAO AI inference subnets
ChainId::Persistence → Backward-compatible LST routing
```

## Security Properties

| Property | Implementation |
|----------|---------------|
| **Replay protection** | SP1 nullifier stored on-chain after each proof verification |
| **Overflow safety** | `overflow-checks = true` in release profile |
| **Pause mechanism** | Admin can pause all operations via `Pause {}` execute |
| **Emergency withdrawal** | Admin can recover stuck funds via `EmergencyWithdraw {}` |
| **Access control** | Relayer registry — only approved addresses can settle tasks |
| **Dust protection** | `min_task_amount` prevents dust-spam attacks |
| **Batch limit** | `max_batch_size = 20` prevents gas exhaustion attacks |
| **ZK proof binding** | Each proof includes `vk_hash` tying it to a specific circuit version |
| **Nullifier scope** | Nullifiers are global (cross-task replay protection) |

### Known Limitations / Out of Scope

- Mock mode: If `mock_mode = true`, proof verification is skipped (testnet only, admin-controlled)
- The contract does not hold OSMO or native Cosmos assets — only ibcTFUEL CW20 tokens
- Cross-chain IBC transfers are initiated by the off-chain relayer (ai-listener.js), not the contract
- Governance whitelisting required before deployment — this proposal is that whitelist request

## Integration Architecture

```
Agent on Osmosis
    │
    ▼ RouteTask { task_id, InferenceRequest, amount: 1_000_000 ibcTFUEL }
ai-verifier.wasm (this contract, Osmosis)
    │
    ├── Stores task, calculates fee (0.5%), emits TaskRouted event
    │
    ▼ (ai-listener.js detects TaskRouted via IBC event polling)
XFuel Backend (Theta side)
    │
    ├── Routes to Theta EdgeCloud (or Akash/Render fallback)
    ├── Generates SP1 Groth16 proof of work
    │
    ▼ SettleTask { task_id, sp1_proof, nullifier, output_hash, fee_commitment }
ai-verifier.wasm (Osmosis, called by relayer)
    │
    ├── Verifies SP1 proof (or mock mode: skip)
    ├── Stores nullifier (replay protection)
    ├── Marks task settled
    ├── Accumulates fee → ForwardFees → FeeCollector.wasm
    │
    ▼ FeeCollector.wasm → IBC transfer back to Theta → CoreRevenueSplitter
```

## Rationale

XFuel is the first protocol to bring ZK-proven AI compute settlements to the Cosmos ecosystem via IBC.
The `ai-verifier` contract is the Cosmos-side settlement point for a pipeline that:

1. Routes AI workloads to Theta EdgeCloud (decentralized GPU, <2s finality)
2. Generates cryptographic proof that the work occurred on the stated hardware
3. Settles payment in ibcTFUEL with automatic fee distribution back to Theta stakers/validators

Without this governance whitelist, the IBC integration remains non-functional — the contract cannot
be deployed, and ibcTFUEL minting is blocked.
